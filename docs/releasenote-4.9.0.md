# v4.9.0 版本说明

> **关键词：** 多 agent 架构修复、调度闭环、权限机制化、归档幂等、完本终态

---

## 一句话

**这版把"文档里架构完整、机制里一半没落地"的问题一次性补齐了——多 agent 协作从"靠模型自觉"变成"靠机制保证"。**

---

## 这版做了什么

之前几版陆续搭起了 8 个 agent 协作写小说的架构，但做架构审计时发现：**很多设计写在了文档里，真正跑起来却不成立**。比如子 agent 完成任务后要"清理 order 文件"，可它们根本没有删除权限——清理不了，调度就会死锁。这类问题共发现 21 处，这版全部修掉。

---

## 怎么做到的

整个修复经历了三轮完整的审计闭环：

1. **multi-agent-systems-architect 架构审计**——逐文件核实每个设计是否真的落地，产出 5 批修复计划
2. **workflow-architect 工作流梳理**——把全系统从主流程到每个 skill 的叶子步骤画成地图，对照发现 14 个缺口
3. **两轮 code review**——人工 + 架构师核实，又补出 11 个问题

每一批修复都伴随真实运行时测试：静态检查（check-agents.py）、沙盒模拟归档、权限矩阵验证，测试发现的问题再交给架构师解决。

---

## 具体改了什么（核心 5 件事）

| 改动 | 说明 |
|------|------|
| **完成信号机制化** | order 文件从"删除 = 完成"改为"标记 `status: DONE` = 完成"——子 agent 用 Write 覆盖状态，不再依赖不存在的删除权限，调度死锁根除 |
| **权限白名单落地** | 8 个 agent 全部加 `tools:` 白名单，权限从"正文里写几行字"变成"harness 真正执行的机制"；新增 `check-agents.py` 在 CI 校验 |
| **归档重写** | 定稿改为"Write 生成 .md、中间稿保留"（不再要求重命名/删除）；归档全程幂等（追加前查重 + 完成 checkpoint），重派不重复 |
| **状态机补全** | 卷完成判定归 novel-agent（数字裁决，不靠作者口述）；新增 `finished` 完本终态 + 完本报告 |
| **数据生命周期** | foreshadowing 伏笔台账从"读而不建"到"模板生成 + 归档维护 + CI 防缺"；reader 评审反馈有落盘沉淀路径；设定变更通知消费闭环 |

---

## 设计原则：写权限最小化 + 数字裁决

两个贯穿始终的原则：

- **最小权限**：每个 agent 能写什么、只能写什么，白名单精确到路径。updater 能创建角色文件，但不能碰正文中间稿；novel-agent 只写 order 和 status.md。权限和职责一一对应，没有"凭自觉"的灰色地带。
- **数字裁决**：卷有没有写完、本书有没有写完，由 novel-agent 数 `chapters/` 里已归档的章节数对比卷纲规划数决定——不是作者随口"继续吧"，也不是 updater 随手打个标记。状态推进有唯一写者，不会两个人写同一个状态互相打架。

---

## 兼容性保证

- ✅ 全新项目 `init.py` 初始化流程不变，自动带出全部新机制（含 foreshadowing 台账、status.md 新字段）
- ✅ 既有项目升级：`sync-project.py` 同步 agent/skill/知识库；foreshadowing 台账缺失时 updater 归档会兜底创建
- ✅ 写作流程本身（设定→卷纲→章纲→提示词→正文→去 AI 味→评审→归档）一脉相承，没变
- ⚠️ 注意：真实项目中遗留的**旧格式 order 文件**（如"状态：已完成"格式）与新完成协议不兼容，升级前建议清理 `.agent/task/` 下的残留 order（仓库内模板已统一，此处仅指历史项目迁移）

## 适合视频呈现的亮点

1. **"文档承诺 vs 机制现实"的审计故事** — 一个设计得再漂亮的系统，机制没落地就是空中楼阁。这次审计发现 21 处"写了但做不到"，每个都伴随真实断链场景（比如子 agent 没有删除权限却要求它删文件）。

2. **三轮审计闭环的工程方法** — 架构师审计 → 工作流梳理 → code review，每轮都产出新问题，每批修复都配真实测试。不是"改完就算"，是"改完测到没话说"。

3. **权限最小化 + 数字裁决的设计取舍** — 用白名单把"agent 能碰什么"钉死，用唯一写者消除状态竞争。这是多 agent 系统从"演示级"到"可靠级"的关键一步。
