# DeepSeek Harness Landing Page 学习总结

> 学习对象：https://www.deepseek.com/harness/（DeepSeek Harness 开发者预览版落地页）
> 学习方法：直接抓取页面 HTML + CSS，提取设计令牌与结构，非肉眼观感
> 结论先行：这套设计的核心是「**近黑底 + 白色 alpha 层级做体积、品牌蓝做点缀、动效做节奏、代码做信任**」

## 1. 技术栈与总体结构

- Next.js 构建，Tailwind + CSS 变量设计系统（`--ds-*` 令牌）
- 单页滚动：导航 → Hero → 概念条 → 设计思路 → 模式卡片 → 自定义产品区 → 安装区 → 生态 CTA → 页脚
- 全页只有一个主张（「一切皆插件」），每个区块都在为它提供证据

## 2. 设计令牌（CSS 原始值）

### 色彩（深色模式）

| 令牌 | 值 | 用途 |
|---|---|---|
| 页面背景 | `#0a0a0a` | 近纯黑沉浸底 |
| 品牌蓝 | `#4d6bfe`（主）`#4176e6` `#3a65c2` `#73a3d2` | 链接、细节点缀 |
| 表面层级 | 白色 alpha：6% / 4% / 2% / 1.5% / 12% | 卡片逐层降低 |
| 描边 | 白 6% / 8% / 20% / 24% | 默认 / subtle / hover / strong |
| 次级文字 | 白 50% alpha | 描述文案 |
| 代码底 | `rgba(0,0,0,.35)` | 命令块 |
| 主按钮 | 白底黑字（primary） | 深色页最高对比元素 |
| Hero CTA | 白 12% 透明底 | 玻璃面板 |

### 字体

- 展示字体：Montserrat / Host Grotesk；正文系统 sans；代码 Fragment Mono / Edit Undo
- Hero h1：60 → 50 → 46 → 38px 阶梯，行高 1.2，字距 0.2px
- 徽标文字 16 → 18px 随断点放大；描述文字 15–18px

### 布局

- 容器：移动 `min(100% - 48px, 1140px)` → 桌面 `min(100% - 160px, 1280px)`
- 间距：8 的倍数 scale（区块 padding 用 `ds-9/10/11/13`）
- 圆角：按钮全圆角 pill（9999px）、卡片 12px、内嵌 8px/7px
- 断点：640 / 768 / 1024 / 1280 四档

## 3. Hero 设计拆解（整页核心）

60/40 网格：左侧文案，右侧视觉。背景三层叠加：

1. **粒子 canvas 层**：`mask: linear-gradient(#000 → transparent)` 顶部渐隐，只露底部粒子
2. **虚焦层**：同 canvas + `blur(20px)`，透明度 0 加载后渐显，制造景深
3. **光晕层**：800px 白色圆 + `mix-blend-mode: screen`，光晕与背景叠加

文案层级（自下而上堆叠，非平铺）：

- 小徽标（16px 白）→ h1（46–60px）→ 两段描述（白 50%，区分信息优先级）→ 4 个 pill CTA
- 每个元素独立「上移 + 模糊消散」入场：`--enter-y:24px; --enter-blur:10px; 0.9s`，子元素延迟 0.15 / 0.3 / 0.4s
- 玻璃 CTA 面板：`linear-gradient(135deg, rgba(255,255,255,0.75) → 0.08 → 0.04 → 0.5)` + 双层白辉光 `0 0 16px + 0 0 32px`

## 4. 交互与动效系统

| 动效 | 实现 |
|---|---|
| 按钮 hover | 伪元素径向涟漪：圆从中心 scale(0→1)，0.36s ease-out |
| 卡片 hover | 内部遮罩层 opacity 0→1，0.3s ease |
| 滚动入场 | 区块 opacity:0 + translateY(20~30px)，进视口浮现 |
| 描边旋转 | `--border-angle` 0→360deg conic-gradient 动画边框 |
| 玻璃导航 | backdrop-blur 24px |
| 光标光环 | 跟随光晕元素 |

## 5. 值得抄的设计决策

1. **一个主张贯穿全页**：视觉元素（插件环、demo 图）全部服务同一叙事
2. **主按钮是白底黑字而非品牌蓝**：深色页上白色是最高对比，蓝只做点缀
3. **动效代替插画**：背景靠 canvas 粒子 + 光晕，产品图全页仅两张
4. **代码即信任**：Hero 第一屏就有安装命令，开发者产品不需要推销话术
5. **响应式克制**：四档断点；移动端 hero 单列、canvas 背景直接隐藏（`hidden md:block`）
6. **信息层级靠透明度不靠颜色**：白 50% / 75% / 100% 三档区分描述、强调、主标题

## 6. 文案内容分析（全页完整文案 + 写作方法）

### 6.1 全页文案清单（提取自页面源码）

- 徽标：`DeepSeek Harness 开发者预览版`
- 标题：`一切皆插件`
- 支撑句 1：`DeepSeek Harness 开发者预览版面向全球 Harness 开发者开放测试，并同步开放源代码。`
- 支撑句 2：`模型、工具、技能、会话、沙箱、存储、循环、调度、UI 等所有 Agent 能力均由插件组合而成，可以自由替换和灵活重组。`
- CTA ×4：`查看 GitHub` / `开发者文档` / `社区插件` / `Cordis 论文`

**概念条**
- 公式：`Agent = Model + Harness`
- 副句：`Harness 让 Agent 在真实场景中持续工作`
- 解释：`模型是 Agent 的灵魂。Harness 给予 Agent 理解环境、使用工具，并在真实场景中持续工作的能力。`

**设计思路（支柱卡：中文名 + 英文名 + 一段解释）**
1. `Cordis 内核` CORDIS KERNEL — `Cordis 内核只负责插件的加载、卸载和依赖关系，不承载 Agent 的具体能力。`
2. `插件提供能力` CAPABILITIES AS PLUGINS — `模型、工具、技能、会话、沙箱、存储、循环、调度、UI 等所有 Agent 能力均由插件提供，并通过 Cordis 服务与事件彼此协作。`
3. `配置层自由组合` COMPOSE IN CONFIGURATION — `开发者无需改动源码，即可在配置层选择、替换或扩展任一能力。`

**模式卡片（名称 + 一句话定位）**

### 6.2 文案方法（可迁移的写作规律）

1. **标题 = 断言，≤6 字**：「一切皆插件」四字定调，解释责任全交给支撑句——标题负责记忆，正文负责说服
2. **区块标题 = 「主张 + 价值」对仗**：「一切皆插件，运行有迹可循」——前半讲是什么，后半讲为什么好
3. **名词堆叠代替形容词**：「模型、工具、技能、会话、沙箱、存储、循环、调度、UI」连排 9 个具体名词，比「全面、强大、灵活」有说服力得多
4. **公式化表达核心思想**：「Agent = Model + Harness」一行等式胜过一段架构说明；随后用「灵魂 vs 能力」对比句拆解分工
5. **CTA 直白命名，零推销词**：全部是「查看 X / 加入 X」式名词短语，没有「立即」「免费」「限时」
6. **卡片描述统一句法**：`是什么 → 支持什么 → 与别人的差异`（「具备标准模式的全部能力，并通过…」——用参照系定位自己，不孤立自夸）
7. **双语标注制造专业感**：支柱卡中文名 + 英文大写名（CORDIS KERNEL），暗示国际化架构
8. **坦诚现状建立信任**：生态区直接声明「仍处于测试阶段，核心插件将持续迭代」——降低预期反而可信
9. **身份 + 承诺的副句结构**：Hero 支撑句 1 说「面向谁开放」（身份），支撑句 2 说「能做到什么」（承诺）

## 7. 对本项目（awesome-novel-agent index.html）的启示

现状差距与借鉴点见 `docs/landing-page-redesign.md`，要点：

- 底子方向一致（深色 + 代码块），差距在**信息层级**（缺主 CTA、强调色过散）与**主张提炼**（缺统摄性口号）
- 移植时只取骨架（Hero 分层、60/40 布局、白按钮 + 单色点缀、动效节奏），粒子 canvas 对单文件静态页过重，不做
