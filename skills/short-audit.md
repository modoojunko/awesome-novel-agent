# short-audit SOP — 契约独立审计

> short-verifier 执行。契约组装完成后、写作开始前的独立闸门。
> 铁律：你没有维护这份契约的包袱，唯一职责是找问题；审计通过的标准是「无足够证据证明有问题」，不是「看起来没问题」。

## 审计五项（每项附原文证据）

1. **转化质量**：抽查契约中来自题材包的招式条目——是否锚定本篇主角（角色名）、信息差（谁瞒谁追）、情绪节奏；发现原文复制或套用痕迹 → FAIL
2. **优先级顺序**：不可违反规则列表是否按 红线 > 字数 > 禁用项 > 叙事规则 > 写作规范同级其他 降序；建议性技法是否混入硬规则区 → 任一颠倒 FAIL
3. **规则去重**：同一对象同一格式的数量线 / 禁止项是否只出现一次；措辞不同但各有侧重的等价约束不算重复 → 完全重复 FAIL
4. **约束间一致性**：情绪与结构约束是否互相矛盾（如「反转一节内完成」vs 反转段占比折算字数；字数下限 vs 压缩策略）→ 任一矛盾 FAIL
5. **条目可核对性**：逐条检视硬规则区——每条是否可被定稿正文核对（机械判定或明确判据）；出现「把握好节奏」类无法核对的表述 → FAIL

## 输出格式

```markdown
# 契约审计报告：{篇名}

| 项 | 结论 | 证据 | 回退目标 |
|----|------|------|---------|
| 转化质量 | PASS/FAIL | 原文引用 | — / 回重组 |
| ... | | | |

## 结论：通过（契约冻结为基线）/ 不通过（回 short-planner 重组后重审）
```

## 约束

- 只报问题与定位，不给修改示范
- 报告自身不得有 AI 腔（审计者本人的措辞也按短篇口径自检）
- 输入缺失（契约未组装完）→ order 退回，不凭记忆审
- 审计通过 → 契约冻结；后续写作与兑现度核对均以冻结版为准，改契约必须重新审计
